Chapter 02

二、契約：同一份清單檔，美術照它畫，遊戲照它收

One Manifest

檔名、尺寸、格式不靠人記：整包交付寫成一份清單檔（manifest），美術照它開工，程式照它收件，兩邊對的是同一份檔案；缺一件、錯一個名，包就出不去。

疑惑

美術交來的檔案，檔名各取各的，尺寸也不齊，每次接圖都要人工對。這種事有辦法一勞永逸嗎？

主張

檔名、尺寸、格式不靠人記：整包交付寫成一份清單檔（manifest），美術照它開工，程式照它收件，兩邊對的是同一份檔案；缺一件、錯一個名，包就出不去。

三分鐘版

接圖那天最累的不是圖好不好看，是對帳。檔名各取各的，尺寸也不齊，程式那邊一個一個改。下一包，重來一遍。兩邊各記各的清單，誰改了誰不知道。

我們把兩份清單併成一份檔案，兩個身分。對美術，它是要畫什麼的清單：哪些件、每件什麼類別、什麼尺寸、放哪個資料夾，一行一件。對程式，它是收件版型：打包照它排資料夾、對檔名，缺一件、錯一個名，包就出不去。沒有「我這邊的版本」。

清單直接算出生產計畫：每槽幾張候選寫在類別上，一展開就是 127 張計畫生成；重試上限每槽加 2，生成預算上限 223 張。要多要少，改一行。

程式那邊不是「照著讀」，是「產生出來」：槽位表程式碼從 manifest 產生，型別、資料夾對應、路徑全生出來，遊戲定義直接匯入（import）。以前同一套詞彙散在七個地方、三種語言，現在只有一個來源。手抄這個動作沒了。

manifest 只管交付長相，不管玩法：賠率、轉輪權重住在另一份手寫的遊戲定義裡。兩份檔案重疊的就是槽位、類別、尺寸、畫布。能安全共用的只有這些。尺度：單一專案的契約，數字出自 demo manifest 與本程式庫（repo）測試。

推導

靠人記為什麼一定漏

兩份清單的問題不在人：美術記一張表，程式記一份常數，改了其中一份，另一份不會自己知道。「同步」沒有人負責。誰都以為對方會做。解法不是更勤勞地同步，是讓第二份清單不存在。

一份檔案，兩個身分

給美術看的那一面：槽位一行一件，id、類別、尺寸；類別再定引擎、候選數、品質檢查（QA）規格、資料夾。版型那面：打包照 folder 排資料夾、照 id 對檔名；缺件、錯名歸閘管，會擋下來，第一章講過。畫布也在裡面：1280×720 橫式，整包共用。同一份檔案，美術開工看它，程式收件也看它。

清單直接算出生產計畫

計畫生成 127 張沒有人另外估，是清單算出來的：每個槽位乘上該類別候選數，加總就是 127。重試上限每槽加 2，生成預算上限 223 張。想調候選數，改一行，計畫跟著變。衍生檔不佔生成數。

程式那邊：產生，不手抄

槽位表程式碼從 manifest 產生：常數陣列、型別、類別對資料夾、變體字尾、路徑產生器，遊戲定義直接 import。改詞彙，重新產生。改不到的地方編譯就報錯。以前同一套詞彙散在七個地方、三種語言；遊戲那邊還有一個硬轉型，把型別檢查關掉。至今沒出過事。現在這種錯不是測試抓到的，是寫不出來。這個做法在第二本第六章有名字：讓錯誤畫不出來。

兩層詞彙：授權與衍生

清單列授權槽：人畫或生成要交的原件。衍生檔產線自動做：每個符號出 _dim 與 _blur、低分符號出 _win、keyart 兩種裁切、logo 大小雙檔、吉祥物三檔。衍生也宣告在 manifest 裡（derives 與 derives_named 欄），產線照宣告做。不宣告，manifest 就變成第二份抄本，跟它要取代的那份清單一樣。

例外磨出來的三條規則

契約不是一次就設計對，是被例外磨出來的。三條：

  • 資料夾可按槽覆寫。jackpot_panel 類別是 plate，檔案卻住 frame/；類別級資料夾不夠用，folder 支援槽級覆寫。
  • 出貨不出貨寫進契約。吉祥物十個部件槽是中間件，拼完就不出貨，標 shipped:false；真出貨的三個檔（mascot.png、mascot.atlas、skeleton.json）改由 derives_named 宣告。
  • 衍生名帶副檔名。三個出貨檔有兩個不是圖片檔（PNG），路徑產生器不准寫死 .png。

輪到你了

這章你是畫的人。你開工前打開的就是這份檔案：你負責哪些件、每件什麼尺寸、什麼類別、放哪個資料夾，一行一件，不用問人。你交回去，閘自動對名對尺寸；對不上，包出不去，錯在哪一件看得到。清單改版，改的是同一份檔案。你跟程式永遠看到同一版。

收據

  1. 契約全文與展開規則（127 的算法、223 上限）

    PLAN.md

  2. 實例：demo manifest（folder、shipped、derives 欄位都在）

    configs/manifest_demo.yaml

  3. 契約的機器可驗形式

    contracts/manifest.schema.json

  4. 槽位程式碼產生器

    pipeline/codegen/slots_ts.py

  5. 衍生照宣告做

    pipeline/stages/derive.py

  6. 遊戲定義讀取生成詞彙的現場

    game/src/core/games/tideglass/game-def.ts

失敗現場

拿詞彙表對倉庫：七個資料夾，六個帳目全對，吉祥物那格兩頭錯。十個部件槽在冊卻從不出貨；真出貨的三個檔，沒有任何地方宣告。

沉澱出來的規則：出貨不出貨寫進契約；在冊以出貨為準，中間件除名。
